## What Went Well

- **Shared infrastructure compounded into a real velocity ramp.** Once the Tool Registry (AD-5), `createLatestWinsRunner()` (AD-16), the clipboard service, and the `ToolError`/`Position` contract (AD-3) existed after Story 1.7, Stories 1.5–1.10 shipped same-day creation-to-done. Stories 1.1–1.4 (repo governance, scaffold, workspace contract, CI), which built that infra from scratch, took multiple days each.
- **Review caught 100% of defects pre-merge.** No bug escaped code review into a merged PR; zero production incidents, because nothing has shipped yet, but also because the review discipline held across all 10 stories.
- **Every story's review consistently separated Patch (fix now) from Defer (log to `deferred-work.md`)**, keeping scope creep low and leaving a persistent paper trail of intentional technical debt rather than silent shortcuts.
- **Regression tests were added for the exact bug class just found**, not just the fix — e.g., 1.7/1.8's key-order tests, 1.9's latest-wins-under-load tests, 1.10's toggle-off-stops-writes tests.
- **A real supply-chain gap was caught by automated security scanning during Story 1.4** (all 6 GitHub Actions pinned to mutable tags, not SHAs) — a class of issue functional code review alone wouldn't have surfaced.
- **The scratch-directory scaffolding discipline from Story 1.2**, adopted directly in response to the project's prior data-loss incident, prevented a repeat by construction — now a standing CLAUDE.md rule, exercised successfully once.

## Challenges

- **Async stale-state / race-condition bugs recurred across 5 of 6 tool stories** (1.5, 1.6, 1.7, 1.8, 1.10) — same shape each time: a toggle or async result landing after application state had already moved on. All caught in review before merge; none reached a user-visible state, but it's the single most repeated review-feedback theme of the epic.
- **Story 1.5's root route rendered correctly under Vitest but was silently blank in the actual production build** — Vue's runtime-only bundle ships no template compiler, and Vitest resolves a different `vue` export than Vite's production build. This was the first screen any user would see, and no automated test caught it; only code review did.
- **IPC/serialization ordering bit twice independently, back-to-back.** Story 1.7 found `serde_json`'s default `Value` map (a `BTreeMap`) silently alphabetizes object keys; Story 1.8, despite that fix already being in place, found a *second* reordering bug — native JS objects received over Tauri IPC get reordered by the ECMAScript canonical-integer-key rule. Two distinct root causes in the same category, not a repeat of the same bug.
- **Testing coverage structurally thins at platform boundaries.** Tauri's macOS webview has no WebDriver support, so keyboard focus, clipboard, and drag-geometry behavior ultimately rest on manual verification — confirmed as a structural gap, not a discipline failure, but still a standing risk.
- **Architecture-doc-vs-reality drift required live reconciliation with the user multiple times** (Story 1.4's runner count, Story 1.3's `ByteOffset` serde variant syntax, Story 1.4's stale AC3 text) — resolved each time by amending the docs rather than silently deviating, but worth naming as recurring overhead.
