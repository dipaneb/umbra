# Story 8.5: Reimagine the JWT Inspector

Status: in-progress

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As the developer,
I want to reconsider the JWT Inspector's feature set through open discovery before redesigning its UI,
so that the redesign reflects a deliberately chosen scope, not a visual reskin of whatever shipped first.

## Acceptance Criteria

**This story ships in two gated tasks (epics.md's own shared Epic 8 shape). Task 1's ACs below are real and testable now. Task 2 (redesign) has no ACs yet — writing them before Task 1's decision record exists would be fiction, per epics.md's explicit instruction — they are added to this story file as a follow-up edit (Task 2a) once Task 1 completes, exactly as Stories 8.1, 8.2, 8.3 and 8.4 did.**

1. **Given** open scope discovery is run for the JWT tool (`bmad-party-mode` or `bmad-forge-idea` — the developer chooses which for this story; a second, narrower pass may follow), framed explicitly as reconsidering the tool's scope from first principles, **when** discovery concludes, **then** a written decision record exists stating what is kept, cut, and added relative to today's shipped implementation, with rationale for each call — the existing implementation is reference only, not a decision to preserve by default. Today's shipped implementation, to be reconsidered rather than assumed:
   - **Decode:** `crates/umbra-core/src/jwt.rs`'s `decode(token: &str) -> Result<JwtDecoded, ToolError>` — trims, splits on `.`, requires **exactly 3 segments**, base64url-decodes `segments[0]` / `segments[1]` via `crate::base64::decode_bytes`, `serde_json::from_slice` each, and rejects a non-**object** header or payload (RFC 7519 §7.2 rule 8). **`segments[2]` (the signature) is split off and entirely discarded** — never decoded, never validated, never surfaced.
   - **Claims:** `numeric_claim` extracts `exp` / `iat` / `nbf` as `Option<i64>` (tolerates a JSON float via `as_f64().map(|f| f as i64)`); every other claim stays in the raw `payload: serde_json::Value`. Return shape `JwtDecoded { header, payload, exp, iat, nbf }`, hand-mirrored in `src/tools/jwt/jwtDecoded.ts`.
   - **View:** `src/tools/jwt/JwtView.vue` (207 lines, **100% pre-Epic-7** — no design tokens anywhere): one `<textarea rows="6">`; a **Decode** button (`AppButton variant="primary"`) that calls `invoke("jwt_decode", { token })`; a **Paste from clipboard** button (`readClipboardText()`); a persistent `.notice` — *"Signatures are not verified — this tool only decodes and displays a token's contents."* On success: `<pre>` blocks for pretty-printed header + payload (`JSON.stringify(v, null, 2)`), a `.claims` `<ul>` of exp/iat/nbf each rendered via `formatDateTime(new Date(value * 1000), settings)` (or `t('tools.jwt.claimNotPresent')` when `null`), and a `role="status"` `p.expired` shown when `isExpired` (`decoded.exp * 1000 < Date.now()`, computed once per decode — not reactive to the clock).
   - **Latest-wins:** a **local** `createLatestWinsRunner()` (`src/shell/invoke.ts`), shared across Decode + Paste. The view's own comment states the reason: *"No drop handler exists for this tool (JWTs are pasted, not dropped), so there's no other caller to coordinate latest-wins ordering with — a local runner is sufficient."* (AD-16 — one runner per independent piece of state; JWT has one.)
   - **Errors:** `jwt-malformed` (segment count ≠ 3 — the count is embedded in the prose message), `jwt-invalid-header` / `jwt-invalid-payload` (base64url or JSON failure — the underlying decoder/serde error text is embedded in the message; `context: "segment: header"` / `"segment: payload"`), `jwt-internal` (join panic). All `ToolError`; all rendered raw via `toolErrorMessage`; **none** is in `TRANSLATABLE_CODES`.
   - **Registry:** `src/stores/registry.ts`'s `jwt` entry — `aliases: ["jwt", "token", "decode", "jeton"]`, `route: "/tools/jwt"`, `icon: "jwt"`, and **`clipboardMatch: { test: matchesJwt, specificity: 3 }`** (added in Story 7.8 — the highest-specificity of the three text matchers; a JWT-shaped string is also base64-shaped, so 3 must beat base64's 1). **No `drop`. No `shortcut`.** `matchesJwt` → `isJwtShaped` in `src/shell/clipboardMatch.ts`: exactly 3 non-empty `.`-separated segments, each matching `/^[A-Za-z0-9_-]+$/`.
   - **No size cap.** Unlike `json.rs` / `base64.rs` / `hash.rs`, `jwt.rs` has **no `MAX_INPUT_BYTES`** and no frontend length ceiling — a giant paste is decoded as-is.
   - **Command:** `src-tauri/src/commands/jwt.rs`'s single `jwt_decode` — `spawn_blocking` (AD-4), `map_join_error` → `jwt-internal`. `src-tauri` has no direct JWT/crypto dependency (AD-1). Registered in `src-tauri/src/lib.rs` (`use commands::jwt::jwt_decode;` + the `generate_handler!` list).
   - **Excluded by Story 2.6 AC4 / FR18 (v1 scope):** "no signature verification is present or implied by the UI … verification is P2 at the earliest." It is now a **P3 backlog candidate** — `epics.md` ~906 lists "JWT signature verification" among the seeded P3 candidates.
2. **Given** the decision record, **when** it is produced, **then** it states whether **FR16** and **FR17** remain accurate, are revised, or are expanded — Epic 8's own preamble makes this revision each story's own output, not predicted in advance. (FR16 — offline decode of header + payload, no JWKS fetch, no network. FR17 — `exp`/`iat`/`nbf` as human-readable local datetimes; expired tokens visibly flagged.)
3. **Given** any idea considered and cut during discovery, **when** the decision record lands, **then** it is captured as a public backlog candidate (FR35) — filed as an individual, max-context GitHub issue on `dipaneb/umbra` with the `backlog-candidate` label per this project's idea-capture convention (cf. issues #113–#116), each linking back to the decision record — **or**, if the developer explicitly directs otherwise (as they did for Stories 8.3 and 8.4), captured in their own tracked backlog and the deviation logged here and in the record so the ideas are traceable, not silently dropped.
4. **Given** the chosen scope, **when** the decision record completes, **then** it states, for the AD-1 functional-core split that Task 2 builds directly on:
   - which parts of `crates/umbra-core/src/jwt.rs` (the `JwtDecoded` struct, `decode` / `decode_segment` / `numeric_claim`, the 11 unit tests) survive as-is versus which need new pure functions — in particular whether **the signature segment stops being discarded** (surfaced raw, and/or verified), and whether a **verification primitive** (`verify(token, key, expected_alg) -> Result<VerificationOutcome, ToolError>` or similar) becomes new core work;
   - whether `src-tauri/src/commands/jwt.rs` changes — the existing `jwt_decode`, a new `jwt_<verb>` command (e.g. `jwt_verify`), or `map_join_error` — and whether `src-tauri/src/lib.rs`'s handler registration changes;
   - whether `src/tools/jwt/jwtDecoded.ts` (the hand-synced TS mirror of the Rust `JwtDecoded` struct — its line-1 comment says keep the two in sync by hand) changes;
   - whether `crates/umbra-core/Cargo.toml` gains a dependency — and if so the exact crate(s), cross-platform-clean and **network-free** (AD-2 / AD-7 / AD-11): a signature-verification path needs either the `jsonwebtoken` crate or RustCrypto primitives (`hmac` + `sha2` for HS*, `rsa` for RS*/PS*, `p256`/`p384` + `ecdsa` for ES*, `ed25519-dalek` for EdDSA); the AD-7 audit (`cargo tree -i reqwest`, plus a direct inspection of any new crate's own dependency list) must confirm no network-capable transitive dependency enters the tree;
   - whether the `jwt` **registry entry** changes — the `clipboardMatch` shape / specificity, a new `shortcut`, or `aliases` — noting that any registry-shape change and any change to `isJwtShaped` / `matchesJwt` in `src/shell/clipboardMatch.ts` is a **shell concern** (AD-6) to present as options with trade-offs, not decide silently inside this story;
   - whether the header/payload rendering **reuses `src/tools/json/JsonTree.vue`** (Story 8.1's collapsible tree + `useCopyFeedback` + `@tanstack/vue-virtual`) instead of a raw `<pre>` — and if so, whether `JsonTree.vue` is treated as a shared component or stays a JSON-tool island (AD-6): a cross-tool-component decision to record, not a silent import.
5. **Given** Task 1 has not yet produced its decision record, **when** this story starts, **then** Task 2 (redesign, and its own Given/When/Then acceptance criteria) has not begun — no implementation starts before the decision record exists.

## Acceptance Criteria — Task 2 (Redesign)

Written 2026-09-02 (Task 2a) from `_bmad-output/implementation-artifacts/8-5-jwt-decision-record.md` and the *JWT Inspector Redesign* canvas (`claude.ai/code/artifact/9ab4c58a-8f60-4cdd-9e71-8bdf32139529`). Developer signed off on this AC set 2026-09-02. Scope is strictly the JWT tool's own files (AD-6) — see Project Structure Notes.

6. **Given** the redesigned `src/tools/jwt/JwtView.vue`, **when** it renders, **then** it is a **single enriched view** — no `AppTabs.vue`, no `AppButton` of any variant, no `primary`-orange control anywhere. The only interactive input is the token `<textarea>`; every other surface is read-only output. Layout order: `h1` → description caption (+ `?`) → token field → (on a successful decode) conditional unsigned-`alg` warning → Header block → Payload block → Claims → expiry/`nbf` status line(s).

7. **Given** text in the token `<textarea>`, **when** the user types or pastes, **then** decoding runs automatically after a **200 ms debounce** (`src/shell/debounce.ts`, `.cancel()` in `onUnmounted`) with no button press; a discrete non-text change (none exist today, but the watch is written to allow one) re-runs immediately. **And** there is **no "Decode" button** and **no "Paste from clipboard" button** — `onDecode`/`onPaste` collapse into one debounced `watch`. **And** the `tools.jwt.decode` and `common.pasteFromClipboard`-driven controls are removed from the template.

8. **Given** a JWT on the OS clipboard, **when** the user is anywhere in the app, **then** the `jwt` registry entry's `clipboardMatch: { test: matchesJwt, specificity: 3 }` still surfaces the tool in the clipboard-suggestion surface exactly as before — `matchesJwt` / `isJwtShaped` / the specificity value are **unchanged** by this story. **And** pasting into the textarea with the OS shortcut populates it and triggers a decode (AC7).

9. **Given** the tool at rest, **when** it renders, **then** a **plain one-line description caption** sits under the `h1` — `--color-text-secondary`, caption type, **no border and no box** — stating that the tool decodes and displays a token and **does not verify signatures**. **And** a `?` affordance next to it opens an `AppPopover` (the `WeakHashPopover` pattern) whose panel carries the longer explanation (a JWT has three parts; this tool reads the header and payload; it cannot tell you a token is genuine or unaltered). **And** the old dashed-border `.notice` element is gone. **And** the honesty statement (caption) is visible at all times, before and after any decode (preserving the Story 2.6 AC4 guarantee).

10. **Given** a successful decode, **when** the output renders, **then** the Header and Payload are each a **tokenised `<pre>`** of `JSON.stringify(value, null, 2)` (`--font-code-*`, `--color-border-hairline` border, `--radius-default`, wrapped) — **not** `JsonTree.vue`, which stays a JSON-tool island. **And** each block has a **~24 px ghost icon-button** (outline copy glyph, no text label, `aria-label` present) top-right, wired through `useCopyFeedback` (`src/tools/json/useCopyFeedback.ts`): `markCopied` only after the clipboard write resolves; `cancelCopyFeedback()` in `onUnmounted` **and** on every fresh decode.

11. **Given** `JwtView.vue` after this story, **when** its `<style>` is inspected, **then** it contains **no** hardcoded colour, radius, or `font-family` — `#666` / `#ccc` / `#b00020` → `--color-text-secondary` / `--color-border-hairline` / `--color-accent-destructive`; `border-radius: 6px` → `--radius-*`; bare `monospace` → `--font-code-family`; every margin/gap → `--spacing-*`. `base.css`'s bare-`<textarea>` styling is consumed, not re-declared.

12. **Given** a decoded header, **when** `alg` is `"none"`, **or** `alg` is absent, **or** `alg` is present but not a string, **then** a **conditional warning** renders — a boxless inline line, `--color-accent-destructive` text + a small triangle glyph, stating the token is unsigned / its algorithm is unreadable and that anyone can create or alter it. **And** when `alg` is a normal string algorithm (`HS256`, `RS256`, `ES256`, …), **no** warning and **no** dedicated "Algorithm" line render — the value is already visible as a line of the Header `<pre>`. Algorithm identifiers are **not** translated (AD-13).

13. **Given** a decoded token whose `exp` is in the past, **when** time passes while the pane stays open, **then** the expired `role="status"` line appears/updates **without a re-decode** — `isExpired` is a computed off a `now` ref reticked by a `setInterval` that is cleared in `onUnmounted`. It is no longer a decode-time snapshot.

14. **Given** a decoded token whose `nbf` is in the future, **when** the output renders, **then** a **"not valid yet"** `role="status"` line renders (sibling to the expired line), naming when the token becomes valid; it clears once `nbf` passes (same live clock as AC13). A token with neither an expired `exp` nor a future `nbf` shows no status line.

15. **Given** the Claims section, **when** `exp` / `iat` / `nbf` render, **then** each present numeric claim shows the **absolute local datetime** (via `formatDateTime` / `src/shell/locale.ts`, honouring the app's locale/date-format settings) **and** a muted **relative time** in parentheses, recomputed off the live clock: the largest whole unit ("in 59 minutes", "3 days ago"), "just now" under ~60 s. An **absent** claim renders "not present" in `--color-text-tertiary` (unchanged wording).

16. **Given** a numeric `exp` / `iat` / `nbf` whose `value * 1000` exceeds `Number.MAX_SAFE_INTEGER` (legal per the Rust `i64` / RFC 7519 `NumericDate`), **when** it renders, **then** `formatClaim` **bounds-checks first** and shows an honest "timestamp out of representable range" message instead of "Invalid Date". No crash. (`deferred-work.md` fold-in #1.)

17. **Given** a registered claim (`exp` / `iat` / `nbf`) that **is present in the payload but is not a JSON number** (string, boolean, array, object, null), **when** the Claims row renders, **then** it shows the raw value plus a **factual note** — e.g. "present, but not a number (string)" — in a muted colour, **not** red, **not** `role="alert"`, and visibly distinct from the "not present" rendering of an absent claim. The view derives this by reading the raw `payload` `Value` for the key; **no `JwtDecoded` / `jwtDecoded.ts` change**. (`deferred-work.md` fold-in #2; open item 4 resolved — "wrong type" means "not a JSON number"; a negative or fractional *number* still renders as a datetime, subject to AC16.)

18. **Given** `crates/umbra-core/src/jwt.rs`, **when** this story lands, **then** it gains a `MAX_INPUT_BYTES` `const` of **1 MB (1_048_576 bytes)** and a byte-length guard at the top of `decode` that returns a new `ToolError` with code **`jwt-input-too-large`** (fixed prose that embeds the byte count) before any splitting; **and** ~3 new unit tests cover at-cap, over-cap, and a normal token being unaffected; **and** `JwtView.vue` mirrors the ceiling on the live path so an over-cap paste never reaches IPC. **And** an over-cap input renders as a calm **`role="status"`** line ("larger than any JWT — nothing was decoded"), **not** a `role="alert"` error. This is the **only** change to `crates/umbra-core/`.

19. **Given** `src/shell/toolError.ts`, **when** this story lands, **then** `TRANSLATABLE_CODES` is **not** extended — `jwt-input-too-large` embeds a runtime byte count so it renders raw, matching `hash-input-too-large` / `json-input-too-large`, and every existing `jwt-*` code still renders raw. **And** new `tools.jwt.*` keys are added to **both** `src/locales/en.json` and `src/locales/fr.json` (description caption, `?`-popover body, unsigned-`alg` warning, wrong-type-claim note, not-valid-yet line, relative-time units, over-cap status line); any string carrying literal `{`/`}` uses the `{'{'}` escape; `src/locales/locales.spec.ts` passes.

20. **Given** the AD-1 split, **when** this story lands, **then**: **no** crypto crate is added (`crates/umbra-core/Cargo.toml` unchanged); **no** `verify` primitive or `VerificationOutcome` type is added and `segments[2]` stays discarded; **no** new command (`jwt_decode` remains the only one, `map_join_error` and `src-tauri/src/lib.rs` registration unchanged); **no** `jwtDecoded.ts` / `JwtDecoded` struct-shape change; **no** `src/stores/registry.ts` or `src/shell/clipboardMatch.ts` change. All humanising/relative-time/`alg`-display/flag logic is **view-side**. One **local** `createLatestWinsRunner()` still backs the single `decoded` write-surface (now the debounced watch) — **not** `registry.getLatestWinsRunner("jwt")` (no drop path). Epoch values stay unix seconds as `i64` across IPC.

21. **Given** the redesigned view, **when** exercised by keyboard and screen reader, **then** it meets the WCAG 2.1 AA floor: every control (the two Copy buttons, the `?` trigger) has an SR label + visible focus; the `AppPopover` follows its built-in focus/Escape/dismiss behaviour; a **successful decode announces its output** via a `role="status"` region (today only the expired sub-line announces — this is the fold-in); errors keep `role="alert"`. The **light + dark `--shadow-floating` render-review** owed on this second app-wide `AppPopover` consumer is performed in the `pnpm tauri dev` visual check of the slice that adds the popover (decision-record open item 3).

22. **Given** `src/tools/jwt/JwtView.spec.ts`, **when** rewritten to the new structure, **then** it still covers: a successful decode renders pretty-printed header + payload; `exp` past → expired `role="status"` present, future → absent, absent → absent; a future `nbf` → "not valid yet" present; a `jwt-malformed` rejection renders via `role="alert"` with the backend message; the description caption / honesty statement is present before any decode **and** after a successful one; a decode that fails after a prior success clears the stale output and shows `role="alert"`; an over-cap input shows the `role="status"` line and no `role="alert"`; a wrong-type `exp`/`iat`/`nbf` shows its factual note and is distinct from "not present"; per-block Copy calls `writeClipboardText` and confirms only after it resolves. `cargo test --workspace` covers the new `MAX_INPUT_BYTES` cases. Full green gate per Task 2b (`pnpm lint` / `pnpm test` / `vue-tsc --noEmit` / `pnpm build` / `cargo fmt --check` / `cargo test --workspace` / `cargo clippy --workspace --all-targets`).

- **What makes JWT different from Hash (8.4) and UUID (8.3) — carry into discovery framing:**
  1. **JWT has no file/drop path and no shared runner.** It uses a plain **local** `createLatestWinsRunner()` (the view says so explicitly). There is no `hash_compute_file` analogue, no `registry.dropResult` consumption, no `DropZone.vue` coordination. Simpler than Hash on this axis — closer to UUID.
  2. **JWT already participates in the clipboard-suggestion surface.** Its registry entry carries `clipboardMatch: { test: matchesJwt, specificity: 3 }` (added in Story 7.8 — Hash and UUID have none). EXPERIENCE.md's Flow 4 uses **JWT as the worked example** ("Amara copies a JWT from her terminal… the JWT Inspector appears at the top of the sidebar"). The redesign must **preserve** that hook, and any change to `isJwtShaped` / `matchesJwt` / the specificity is a **shell concern** (AD-6) — present it as options, don't tune it silently.
  3. **JWT already renders structured JSON** — pretty-printed via `JSON.stringify(v, null, 2)` in a `<pre>`. Story 8.1 built a real collapsible tree viewer (`src/tools/json/JsonTree.vue` — expand/collapse, `useCopyFeedback`, `@tanstack/vue-virtual`). The obvious "Changed" candidate is to render header + payload through that tree instead of a raw `<pre>`. **Whether `JsonTree.vue` is a shared component or a JSON-tool island is an AD-6 decision to record** (it currently lives under `src/tools/json/`; `useCopyFeedback` is already imported cross-tool from there with a hoist-candidate comment — the hoist is deliberately *not* done).
  4. **The signature is thrown away.** `segments[2]` is split off and never touched. This is the single biggest keep/cut/add question. Three distinct directions, not one: (a) **surface the raw signature segment** (display-only, zero crypto) — cheap, honest, no dependency; (b) **offline signature verification** — paste a secret (HS*) or a PEM/JWK public key (RS*/PS*/ES*/EdDSA), verify, show pass/fail as a `role="status"` result — a real second job (needs a crate: `jsonwebtoken`, or RustCrypto `hmac`/`rsa`/`p256`/`ed25519-dalek`; AD-2/AD-7/AD-11 audit required; genuinely justifies `AppTabs.vue` Decode / Verify — 8.3's record noted "an inspector *would* have been the second job that justifies tabs"); (c) **stay decode-only** and keep the "not verified" notice, treating verification as the P3 backlog item it already is. FR18 / Story 2.6 AC4 said "no verification present or implied … P2 at earliest" — Epic 8's preamble makes revising that this story's own call.
  5. **`alg` is buried in the raw header `<pre>`.** jwt.io and every serious inspector surface the header algorithm prominently and warn on `alg: none` and algorithm-confusion setups — a security-education angle with near-zero implementation cost (it's already in `decoded.header`).
  6. **The expired flag is a decode-time snapshot.** `isExpired` reads `Date.now()` once, at decode. It never updates as the clock advances, and `nbf`-in-the-future ("not yet valid") is not flagged at all — only `exp`-in-the-past. A live clock and an `nbf` flag are small "Added" candidates.
  7. **No size cap.** `jwt.rs` has no `MAX_INPUT_BYTES` and the view has no length ceiling. If Task 2 moves to live as-you-type decoding (the 8.2/8.3/8.4 direction), it wants a debounce **and** a length ceiling, and a decision on whether a real cap belongs in core (the other three tools all have one).
  8. **JWT decode is trivially fast** — base64url + `serde_json` parse of two small segments, microseconds. There is no `spawn_blocking`-cost argument for keeping an explicit Decode button; `jwt_decode` runs on the blocking pool only for AD-4 consistency, not need.
