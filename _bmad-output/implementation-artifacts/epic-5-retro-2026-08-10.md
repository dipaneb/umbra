## What Went Well

- **The Epic 4 retro's spine rule (dependency version/API drift) got used immediately, twice.** Story 5.1 resolved a real `tauri-action@v0` vs. `@v1` doc conflict by querying GitHub's API directly instead of trusting either source; Story 5.2 did the same for `tauri-plugin-updater`/`tauri-plugin-process`. Two epics running now where a retro action item closed the loop into real use without rediscovery (AD-16 did the same from Epic 3 into Epic 4).
- **"Coding complete" vs. "fully verified" stayed cleanly separated, for the first time this explicitly.** Story 5.1 named this distinction outright in its own Dev Notes and held to it — AC1–AC3 weren't marked satisfied until a real signed prerelease tag proved every clause, byte-for-byte (the `latest.json` signature key ID checked against `tauri.conf.json`'s pubkey, not assumed).
- **Code review kept catching real bugs, not just style.** Story 5.2's review caught a genuine consent-safety bug: a user could click Install then Not Now mid-download, the dialog would hide, but the install could still force a relaunch after the user believed they'd declined — exactly the failure a consent-focused story exists to prevent.
- **The two-repo boundary (Story 5.4) held.** First time this project touched a second repository; `Umbra`'s own tree only ever gained one line (the spine's Deferred-item resolution), verified via `git status --porcelain` after nearly every task.

## Challenges

- **A second occurrence of the same PII-leak failure mode.** Story 5.1 committed and pushed the developer's real full name and a real local filesystem path to the public repo, without asking first — the exact incident class `CLAUDE.md`'s "this repo is public" section already existed to prevent, following an earlier, similar leak. The `guard-commit-privacy.sh` hook was already in place before this session started and, per the story's own record, did not fire during the actual `git commit` calls that introduced the leak — an open, unexplained technical question, not a resolved one. Remediated via a force-push history rewrite; ~80 minutes of public exposure before the fix landed.
- **New shared infrastructure didn't inherit this project's own governance precedent.** Story 5.4 stood up `umbra-web`, a second public repo — but it shipped with no LICENSE file and no branch protection on `main`, while `Umbra` itself has had both since Story 1.1 ("A governed public repository"). The stack/hosting decision itself (Astro, separate repo, Vercel) was reasoned well, but was presented to the developer as already-decided rather than as options to weigh in on first — and the governance checklist simply never got re-triggered for the new repo.
- **A drafting slip caught mid-session, not before.** Story 5.5's own task list said "11" candidates in three places while the AC and its own table both named 12 — caught via self-verification and confirmed with the developer before the `gh issue create` calls ran, not before the story was drafted.
