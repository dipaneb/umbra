Shapes + Elevation, round 4 — border opacity sweep, light + dark

Radius (4px) and border-over-tonal-lift are now locked from round 3. What's still open is how visible that border should be — every render so far used a hand-tuned solid hex (#E2E4E7 light / #2C2C2F dark) that may be too strong. This round swaps to rgba border color instead of solid hex, so the same opacity percentage produces a matched result in both modes automatically, and sweeps five values — 4%, 6%, 8%, 10%, 12% — so the developer can pick the subtlety level directly rather than tune two hex values by eye.

Why rgba instead of hex this round: a solid hex border has to be re-tuned separately for light and dark to look equivalently subtle. rgba(16,17,19,a) in light mode and rgba(255,255,255,a) in dark mode — same alpha, opposite base color — produces a matched visual weight in both modes from one shared number. That's the entire point of testing opacity as the variable this round instead of another pair of hex codes.
How to compare: scan down the page from V1 (4%, most subtle) to V5 (12%, most visible). V3 (8%) is flagged as the closest match to the old solid-hex baseline you've seen in every prior render — use it as your anchor, then judge whether you want to land lighter (V1/V2) or keep roughly where things already were (V3) or go slightly firmer (V4/V5).
